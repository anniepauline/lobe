Lobe — Brainstorm Report

Intelligent bookmarking extension with an AI taste layer · August 12, 2026
The core insight: this is not a smart bookmarks product. It is a personal taste layer for AI. Bookmarks today are a write-only graveyard: you save and never return. The twist here is that every save becomes queryable context, exposed to Claude and ChatGPT via MCP, that knows why you saved something. That is the moat. The save button is just the intake pipe.

Why this is different

Existing tools (mymind, Raindrop, Fabric) store things. None of them feed your taste back into the AI tools where you actually think and build. The loop that matters:

  1. Save anywhere with near-zero friction, ideally through a native-feeling button injected into the page.
  2. Auto-organize with intent, not just topic: "want to try this tool" vs. "want to build something similar" are different categories even for the same tweet.
  3. Talk to it: semantic search, and an MCP server so any AI assistant can pull from your saves and your taste profile.

The demo that sells the whole product: "Claude, what tools did I save last month that I wanted to clone?" and it answers correctly.

The four genuinely hard problems

1. Universal DOM injection engineering treadmill

"Scan any site, find where the thread lives, place or replace the bookmark button" is a selector-discovery problem. Twitter changes its markup weekly. The feasible approach: an LLM derives a selector recipe once per site and layout, the recipe is cached and shared across users, and when it breaks the system re-derives and pushes the fix to everyone. This is novel and workable, but it is a permanent maintenance cost. Budget for it forever.

2. Content capture solvable cheaply

The X API is expensive, Instagram is walled, articles are paywalled. The sidestep: the user is already logged in and the content is already on screen. Snapshot the DOM text plus a screenshot at the moment of the save click. No platform APIs needed. This is a big simplification and it works everywhere.

3. Intent inference good design already sketched

Asking a question on every save kills the UX. Use a confidence threshold: auto-assign when the model is sure, show a one-tap chip ("Try it" / "Build similar" / "Reference") when it is not. Onboarding seeds the priors, ongoing feedback tunes them. Over time the questions disappear. This matches the original description and is the right shape.

4. Passive interest detection cut from v1

"It figures out you like the website" means the extension reads every page you visit. That is a scary permission, a slow Chrome Web Store review, a real privacy story to defend, and a ruinous LLM bill if pages are scanned in the cloud. Ship explicit-save only in v1. Passive detection is a v3 feature, and probably only viable with an on-device model.

Competitive landscape

ProductWhat it doesWhat it lacks
mymind Closest competitor. Auto-categorized, no folders, visual-first. No intent capture, no MCP/AI integration, no in-page save buttons.
Raindrop Folders and tags, manual organization, power-user oriented. All the organizing burden is on the user. No intelligence.
Rewind / Limitless Capture everything you see automatically. No curation signal. A deliberate save is a high-value data point; recording everything drowns it.

The gap is real, and the window is open because MCP adoption is fresh. Nobody owns "your saves as AI context" yet.

MVP cut

  1. Extension (WXT, TypeScript): keyboard shortcut and context-menu save that work on every site. Injected native-feeling button on exactly three hand-tuned targets: X, YouTube, and generic articles via Readability. Hand-write the recipes; the auto-discovery magic comes later, after the recipe format is proven.
  2. Save pipeline: DOM snapshot → Haiku categorizes and extracts intent → embed → Postgres + pgvector. One service, no microservices.
  3. Web app: semantic search and category browsing.
  4. MCP server reading the same database, exposing search_saves and get_taste_profile. This is the launch demo.
  5. New-tab homepage ("thoughts of the day"): v2. Good retention hook, not the core loop.
Sequencing rule: the save → auto-organize → talk-to-it loop must feel like magic before anything passive or homepage-shaped gets built.

Name

Lobe is short, the brain metaphor fits, and it is brandable. Two problems: Microsoft previously owned Lobe (lobe.ai, the ML training tool, shut down in 2022), so a trademark and domain check is required; and your own gut already flags it as weird. The demographic split from your polling (Gen Z → Lobe, 25+ → In-N-Out, 35+ → Synapsis) is interesting but the sample is small, so do not overweight it. Synapsis reads as dated enterprise software. Decide late; the name matters far less than the demo.

Costs and risks

  • Per-save LLM cost: a fraction of a cent with Haiku. Fine at any realistic scale.
  • Passive page scanning: ruinous in the cloud. Another reason it is cut from v1.
  • Chrome review: broad host permissions (<all_urls>) slow review. Prepare the privacy policy early and request the narrowest permissions the injected buttons allow.
  • Platform fragility: injected buttons will break when sites redeploy. The shared, self-healing recipe cache is the mitigation, and it needs telemetry from day one.
Verdict: build the MVP. Lead with the MCP angle, not the bookmark button. Cut passive detection entirely from v1. Hand-tune three sites before attempting auto-discovery. The product wins if the first "talk to your saves" demo feels like magic.
